La página solo compone piezas compartidas de iroFactory, sin dependencias más allá de las fuentes. El fondo es una cuadrícula con nodos que flotan y se conectan entre sí, y la cuadrícula se ilumina bajo el cursor.

Las secciones de abajo se recorren desde el dock: cada ícono es una estación, y cada panel se carga la primera vez que se visita.

    Guía de guardia: latencia alta en la API

    Qué hacer cuando la API responde lento: de la alerta al análisis posterior.

    Síntomas

    • La alerta api-latency-p95 pasa de 800 ms durante 5 minutos.
    • El tablero de estado marca Demora en la API pública.
    • Aumentan los reintentos en el cliente móvil.

    Qué hacer

    1. Declara el incidente en el canal #incidentes y asigna quién coordina.
    2. Revisa el último despliegue: si fue hace menos de una hora, regrésalo antes de investigar.
    3. Mira la base de datos: conexiones activas y consultas lentas.
    4. Actualiza la página de estado cada 30 minutos aunque no haya novedades1.
    kubectl rollout undo deployment/api -n prod
kubectl rollout status deployment/api -n prod

    En la terminal del tablero, g luego s abre el estado y / busca un servicio.

    Niveles de severidad

    SEV1
    Servicio caído para todos. Se avisa a dirección.
    SEV2
    Función principal degradada o caída para una parte.
    SEV3
    Molestia menor con solución alterna.

    La esperanza no es una estrategia.

    Lema de los equipos de confiabilidad de sitios (SRE)

    Después

    ¿Cuándo se escribe el análisis?

    En los tres días hábiles siguientes, sin culpables: qué pasó, por qué, y qué cambia para que no se repita.

    ¿Quién cierra el incidente?

    Quien coordina, cuando la métrica lleva 30 minutos estable y la página de estado ya dice Resuelto.

    1. Un estado sin cambios también informa: la gente deja de preguntar por otros canales. ↩
